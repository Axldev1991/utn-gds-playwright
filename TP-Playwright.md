# Playwright

## Objetivo
El objetivo de la actividad es que el alumno se familiarice con el uso de Playwright para realizar tareas de testing automatizado sobre aplicaciones web, incorporando el uso de inteligencia artificial generativa para la generación y adaptación dinámica de casos de prueba, especialmente en el contexto de Single Page Applications (SPA) donde el DOM cambia de forma dinámica y los selectores tradicionales tienden a romperse con facilidad.

## Puntos a Desarrollar
- Explicar qué es Playwright y en qué se diferencia de otras herramientas de testing end-to-end (Selenium, Cypress).
- Explicar concepto de QA adaptativo y por qué las SPAs representan un desafío particular para el testing automatizado tradicional (selectores frágiles, contenido asincrónico, rutas client-side).
- Explicar cómo se puede combinar Playwright con un modelo de lenguaje (LLM) para generar o ajustar selectores y casos de prueba de forma dinámica ante cambios en la interfaz.
- Listar y explicar los principales componentes de Playwright utilizados en la actividad: Locators, Page Object Model, fixtures, trace viewer, y su rol en la mantenibilidad de los tests.
- Seleccionar una SPA (propia o pública) sobre la cual se ejecutarán las pruebas.
- Redactar una spec de testing que incluya: contexto de la aplicación, flujos críticos a cubrir, criterios de aceptación por cada test, y restricciones técnicas (navegadores, viewport, datos de prueba).
- Implementar un conjunto de tests con Playwright que cubran al menos tres flujos funcionales distintos (por ejemplo: login, búsqueda, alta de un registro).
- Ejecutar la suite de tests y mostrar evidencia de resultados (reporte HTML de Playwright, trace viewer o video de ejecución).
- Elaborar el video de presentación.
